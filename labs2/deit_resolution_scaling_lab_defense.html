  • Dataset: Imagewoof (10 challenging dog breeds from ImageNet; 9,025 train / 3,929 val).

Data Integrity Decision Crucial Control

Standard imagewoof2-320 pre-downscales all images so the shortest edge is 320 px.

Upscaling 320 px images to 384×384 introduces synthetic interpolation blur into the inputs. To test whether genuine optical detail helps, we use full-resolution raw Imagewoof images.

Crucially, we rejected the standard Imagewoof-320 package because upsampling 320-pixel images to 384 only feeds interpolation blur into the network; using full-size raw photos ensures we test genuine high-frequency optical information against our 97.20% zero-shot baseline.
PART 1 • Piotr Sitek

What Breaks at 384×384: Positional Embedding Surgery

Slide 3 / 11
1. Patch Grid @ 224×224
P = 16 → (224 / 16)² = 196 patches

14×14 spatial grid + 2 special tokens (CLS, DIST) = 198 tokens.

2. Patch Grid @ 384×384
P = 16 → (384 / 16)² = 576 patches

24×24 spatial grid + 2 special tokens (CLS, DIST) = 578 tokens.

3. The Runtime Failure
pos_embed: [1, 198, 384] vs [B, 578, 384]

Element-wise addition x + pos_embed fails immediately without manual 2D resizing.

Manual 5-Step Tensor Resizing Pipeline (No Pre-Built timm Helpers)
Step 1: Slice Tokens
[1, 198, 384]

Separate cls (idx 0) & dist (idx 1) from the 196 patch embeddings.

Step 2: 2D Reshape
[1, 384, 14, 14]

View [1,196,384] as [1,14,14,384] and permute channels first.

Step 3: Interpolate
14×14 → 24×24

Apply 2D F.interpolate (bicubic, align_corners=False).

Step 4: Re-Attach
[1, 578, 384]

Permute & flatten to [1,576,384]; concat [cls, dist, patches].

Step 5: Metadata Sync
grid_size=(24,24)

Update patch_embed.img_size = (384,384) to pass internal assertions.

cls_dist_pe = pos_embed[:, :2, :]                                           # [1, 2, 384]   (Keep special tokens untouched)
patch_pe    = pos_embed[:, 2:, :].reshape(1, 14, 14, 384).permute(0,3,1,2)  # [1, 384, 14, 14]
patch_pe    = F.interpolate(patch_pe, size=(24, 24), mode='bicubic', align_corners=False)
patch_pe    = patch_pe.permute(0, 2, 3, 1).reshape(1, 576, 384)             # [1, 576, 384]
model.pos_embed = nn.Parameter(torch.cat([cls_dist_pe, patch_pe], dim=1))   # [1, 578, 384]
[Speaker Notes — Piotr]: With a 16x16 patch size, moving from 224 to 384 increases the patch sequence from 196 to 576 tokens, causing an immediate shape mismatch against the pre-trained 198-token positional embedding. Following the assignment rules, we manually sliced off the non-spatial CLS and distillation tokens so they wouldn't corrupt spatial borders, reshaped the 196 patch embeddings into a 14x14 2D feature map, applied 2D interpolation to 24x24, flattened back to 576 tokens, and re-concatenated the special tokens to form a [1, 578, 384] parameter.

Solution D: Selective Layer Freezing

Slide 6 / 11
Architectural Hypothesis (What D Tests)

Early blocks (0–7) mostly capture lower-level features learned well on ImageNet; freezing them cuts the number of trainable parameters and may reduce overfitting on 9,025 images. Late blocks (8–11) are given the chance to adapt to the 24×24 grid.

Caveat: pos_embed is added before block 0, and each 16×16 patch covers a smaller part of the dog at 384, so the frozen blocks also see shifted inputs and cannot adapt to them.

Parameter Allocation (8.09M Trainable / 35.8% of Model)
FROZEN (64.2%)
patch_embed
CLS / DIST tokens
Blocks 0 – 7
not trained
TRAINABLE BACKBONE
pos_embed + norm
Blocks 8 – 11
lr = 5e-5
TRAINABLE HEADS
head (CLS)
head_dist (DIST)
lr = 5e-4
Training Objective (Same as B and C)

Plain cross-entropy on the 10 dog logits. In training mode timm returns the average of the two heads, so one loss trains both:

ℒ = CE( ½(zcls + zdist)[:, to_imagenet], ytrue )

No teacher / distillation: D keeps the same loss as C, so D vs C isolates the effect of freezing. AdamW (wd=0.05), cosine to 1e-6, 11 epochs, batch 32.

Solution D Result (11 Epochs, Final Epoch)
Blocks 8–11 + PE + norm + both heads
Validation Accuracy: 97.20%
vs 224 0-Shot (97.20%): +0.00% (same 3,819 imgs) vs 224 Control (97.30%): -0.10%
Same D recipe @224: 97.38% 384 vs 224: -0.18% (-7 imgs)
How to Read D

1. D vs C (same loss, everything trainable): the effect of freezing blocks 0–7. D vs B2: the effect of also training blocks 8–11 and the final norm.

2. Possible explanation if D trails C (hypothesis, not measured): blocks 0–7 are not purely local filters; their self-attention spans all 578 tokens with weights trained for 198, and frozen, they cannot recalibrate.

[Speaker Notes — Gabriela]: Solution D sits between B and C: the patch embedding, the CLS and DIST tokens and blocks 0 to 7 stay frozen, while blocks 8 to 11, the final norm, the positional embedding and both heads are trained, about 8.1 million parameters or 36% of the model. The loss is the same plain cross-entropy as in B and C, with no teacher, so comparing D with C shows the effect of freezing alone. D reached 97.20%, exactly the same 3,819 correct images as the untouched model at 224, and 0.10 points below the 97.30% fine-tuning control. When we run the very same D recipe at 224, it gets 97.38%, so at 384 the same recipe loses 7 images. During training the training loss kept falling, from about 0.21 to 0.10, while validation stayed around 97.1 to 97.2%: the extra trainable parameters fit the training photos better without helping on new ones. Our hypothesis is that even early ViT blocks use global self-attention over all 578 tokens, so keeping them frozen limits how far the model can adapt to the new resolution; we did not measure this directly.

Possible Mechanism (Hypothesis, Not Measured)

Going from 198 to 578 tokens grows each attention matrix from 39,204 to 334,084 pairs (8.5×), and every softmax is spread over ~3× more tokens in every block. Frozen blocks cannot recalibrate to this. Consistent with that, the 384 penalty is largest when everything but the heads is frozen (B1, −17 images) and smaller when blocks 8–11 also train (D, −7). A direct test would compare attention entropy at 224 and 384.

Solution E: Progressive Resolution Curriculum (224 → 384)

Slide 9 / 11
Engineering Pitfall & Clean Fix: Avoiding Compounding Blur

The Trap: Sequentially interpolating 14×14 → 16×16 → 20×20 → 24×24 repeatedly resamples already-smoothed tensors, compounding bicubic blur and degrading high-frequency positional signals.

Our Fix: Cache the pristine 14×14 base positional embedding before training and interpolate directly from 14×14 at each resolution transition.

4-Stage Curriculum Schedule (Total = 11 Epochs / 99,275 Images)
Stage Res. (Grid) Epochs Backbone LR Stage Val Acc
Stage 1 224² (14×14) 4 ep 5e-5 96.33%
Stage 2 256² (16×16) 4 ep 2e-5 97.12%
Stage 3 320² (20×20) 1 ep 1e-5 97.00%
Stage 4 (Final) 384² (24×24) 2 ep 5e-6 97.38%
Solution E Final Result
Progressive Resolution Curriculum (224 → 256 → 320 → 384)
Validation Accuracy @ 384: 97.38%
vs 224 Base: +0.18% vs 224 Control: +0.08%
Why Did Direct 384 FT (97.58%) Beat Progressive (97.38%)?

1. Budget Fragmentation: Under the strict 11-epoch cap, spending 9 epochs at intermediate resolutions leaves only 2 epochs at 384×384—insufficient for full convergence on the 24×24 grid.

2. Repeated Transition Shocks: Every resolution jump resets positional embeddings from the 14×14 base, forcing the backbone to re-adapt 3 separate times instead of once.

[Speaker Notes — Vitaliy]: In Solution E, we tested whether easing the resolution shock via a progressive curriculum—224 to 256, 320, and finally 384—would outperform jumping straight to 384. To prevent compounding interpolation blur across stages, we cached the original 14x14 positional embedding and interpolated freshly from that base at each step. While Solution E reached 97.38%—beating both the 97.20% baseline and 97.30% control—it trailed Solution C's 97.58% because our 11-epoch cap left only 2 epochs at the final 384x384 target resolution.

PART 3 • Vitaliy Khomyn

Key Architectural Insights & Defense Q&A

Slide 11 / 11
1. Positional Interpolation Is Necessary but Insufficient

Isolating CLS/DIST tokens and applying 2D bicubic interpolation fixes tensor geometry, but induces an immediate -0.51% accuracy drop until self-attention projections adapt.

2. The Scientific Control Mandate

Comparing 384 fine-tuning only against 224 zero-shot conflates domain shift with resolution scaling. Our 224 control run proved that +0.10% is class specialization and +0.28% is true optical gain.

3. Partial vs. Full Adaptation

ViT self-attention spans all tokens in every block (198² → 578² pairs), so a resolution change reaches every layer, not only the input. Partial tuning (B1, B2, D) reached 96.97–97.20% at 384, below the same recipes at 224 (97.38–97.40%), vs 97.58% for full fine-tuning; our hypothesis is that frozen blocks limit how far the model can adapt.

4. Budget Allocation Under Tight Compute Caps

Under a strict 100k-image (11-epoch) cap, dedicating all 11 epochs directly to 384×384 with differential LRs (97.58%) outperforms splitting epochs across a progressive curriculum (97.38%).
